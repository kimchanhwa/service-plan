1어떤 서비스를 만들고 싶은지?

교통약자(유모차·휠체어 사용자, 고령자, 장애인 등)를 위한 안전 경로 안내 서비스입니다.

두 종류의 정보를 결합해 경로의 위험도를 판단합니다.

⛰️ 원래 가기 힘든 길 (고정 정보)

DEM과 도로 선 데이터로 도로 구간별 경사도를 미리 계산

🚗 지금 가기 힘든 길 (실시간 정보)

CCTV 영상에서 갓길 주차 차량을 인식해 남은 통행 폭을 계산

핵심 기능

  1. 도로 경사도 계산: 경사도(%) = 높이 차이 ÷ 수평 거리 × 100
  2. 갓길·골목 주차 차량 인식: 영상에서 차량과 도로 영역을 인식하고, 일정 시간 이상 멈춰 있는 차량을 "주차"로 판단
  3. 위험도 측정: 도로 폭 대비 주차 차량이 차지한 폭으로 남은 통행 폭을 계산하고 경사도와 합쳐 위험도 산출
  4. 맞춤 경로 추천: 사용자 이동 유형에 맞춰 경사, 통행 폭, 장애물을 고려한 "편한 길"과 대안 경로 제시

위험도 계산 예시

남은 통행 폭 = 도로 폭 − 주차 차량이 차지한 폭

남은 폭 ≥ 2.0m   → 🟢 안전
1.2 ~ 2.0m      → 🟡 주의 (휠체어 통과 가능, 차와 마주치면 위험)
< 1.2m          → 🔴 위험 (휠체어·유모차 통과 어려움)

+ 경사도를 가중치로 반영 → "좁고 가파른 길 = 매우 위험"

면적 비율보다 남은 통행 폭을 기준으로 하는 이유는 교통약자에게 중요한 것이 "도로의 몇 %가 막혔나"가 아니라 "휠체어가 지나갈 폭이 남아 있나"이기 때문입니다.

서비스 구조

[DEM + 도로 선 데이터] → 도로 구간별 경사도 (미리 한 번 계산)
[실시간 CCTV / 제보 사진] → AI 분석 → 구간별 주차 차량·남은 통행 폭 (몇 분마다 갱신)
[공공 API]              → 엘리베이터·저상버스·날씨·편의시설 등
          ↓
   사용자 이동 유형에 맞춘 위험도 계산
          ↓
   경로 추천 + 위험 구간 경고 + 대안 경로

⑥ 사용하는 AI 기술 (Vision AI)

이 서비스의 영상 분석은 모두 Vision AI(컴퓨터 비전) 기술입니다.

측정용 Vision AI: 정확한 수치 계산 담당

  • 세그멘테이션 (YOLO-seg 등): 차량과 도로 영역을 픽셀 단위로 인식
  • 객체 추적 (ByteTrack 등): 같은 위치에 1~2분 이상 멈춰 있는 차량을 "주차"로 판단
  • 원근 보정 (버드뷰 변환): 카메라마다 바닥 기준점 4개를 지정해 위에서 내려다본 시점으로 바꾼 뒤 실제 크기(m)를 계산

이해용 Vision AI (비전-언어 모델, VLM): 상황 설명과 예외 상황 담당

  • 학습하지 않은 장애물 인식: 쓰러진 킥보드, 공사 자재, 쓰레기 더미, 파손된 보도블록 등
  • 상황 설명 문장 생성: "인도 오른쪽에 차량 2대가 주차되어 통행 폭이 좁습니다" → 시각장애인 음성 안내에 활용
  • 사용자 제보 사진 검증·분류: 제보 내용이 사진과 맞는지 확인하고 유형을 자동으로 분류
구분측정용 (YOLO 등)이해용 (VLM)
잘하는 것정확한 위치·크기 측정, 빠른 실시간 처리처음 보는 물체 이해, 자연어 설명
약한 것학습하지 않은 물체는 인식하지 못함m 단위 수치 측정은 부정확함, 느리고 호출 비용이 듦
이 서비스에서 역할통행 폭·위험도 계산 (핵심)쓰러진 킥보드나 공사 자재 같은 예외 장애물 감지, 시각장애인용 음성 설명, 제보 사진 검증 (보조)
추천 구조: 실시간 수치 계산은 YOLO 같은 측정용 모델이 맡고, VLM은 위험 구간으로 판정된 장면이나 제보 사진에만 호출해서 설명과 예외 상황을 보완합니다. 이렇게 하면 비용과 속도 부담을 줄일 수 있습니다.

3입력값과 출력값이 무엇인가?

서비스를 AI 분석 단계와 사용자 서비스 단계, 두 층으로 나눠 설계합니다.

[분석]   영상·사진 + 카메라·도로 정보        → 도로 구간별 측정값
[서비스] 사용자 요청(출발지, 목적지, 이동 유형) → 맞춤 경로 + 위험 구간 안내

A. AI 분석 단계: 입력값

입력내용출처갱신
이미지 / 영상 프레임CCTV 프레임 또는 사용자 제보 사진국가교통정보센터, 제보, 공개 데이터셋실시간
카메라 정보카메라 ID, 위치(위도·경도), 비추는 도로 구간 IDCCTV API고정

A. AI 분석 단계: 출력값 (도로 구간마다 하나)

{
  "segment_id": "SEG_00123",
  "timestamp": "2026-10-13T14:30:00",
  "source": "cctv",
  "parked_vehicles": 3,
  "road_width_m": 4.0,
  "remaining_width_m": 1.1,
  "slope_percent": 8.5,
  "confidence": 0.87
}
AI 분석은 측정값(남은 폭, 경사, 차량 수)까지만 출력하고, 위험 등급은 서비스 단계에서 사용자 유형에 맞춰 계산합니다. 그래야 같은 분석 결과를 모든 사용자 유형에 다시 쓸 수 있습니다.

B. 사용자 서비스 단계: 출력값

{
  "route": [ /* 경로 좌표 목록 */ ],
  "total_distance_m": 850,
  "estimated_time_min": 14,
  "max_slope_percent": 5.2,
  "warnings": [

4타겟층

유모차·휠체어 사용자, 고령자, 장애인 등 이동에 어려움이 있는 교통약자

사용자 유형별 기준값 (예시)

유형최대 허용 경사필요한 통행 폭특히 위험한 것
수동 휠체어약 5~8%1.2m 이상오르막·내리막, 턱
전동 휠체어약 8~10%1.2m 이상좁은 길, 턱
유모차약 8%0.9m 이상턱, 울퉁불퉁한 노면
고령자 (도보)약 8~10%0.9m 이상긴 오르막, 결빙, 쉴 곳 없는 긴 구간
시각장애인경사 영향 적음0.9m 이상갓길 주차 차량·장애물
한국 장애인등편의법은 경사로 기울기를 보통 1/12(약 8.3%) 이하, 보도 유효폭을 1.2m 이상으로 정하고 있습니다. 서비스 기준을 확정하기 전에 법령 원문을 확인해야 합니다. 표의 값은 출발점이며, 사용자가 "내 최대 경사"를 직접 조절할 수 있게 합니다.

같은 구간, 다른 위험도

남은 폭 1.1m, 경사 6%인 구간
  → 수동 휠체어: 🔴 위험 (폭 부족 + 경사 부담)
  → 유모차:     🟡 주의
  → 시각장애인: 🟡 주의 (장애물 있음 알림)

앱 접근성 설계

  • 큰 글씨와 버튼, 단순한 화면 (고령자)
  • 스크린리더 지원, 음성 안내 (시각장애인)
  • 색으로만 구분하지 않기: 🔴🟡🟢에 아이콘이나 글자를 함께 표시
  • 첫 실행 때 이동 유형을 한 번만 선택하고 이후에는 자동 적용

5그 외

현실적인 제약: 골목길 CCTV

국가교통정보센터와 TOPIS의 공개 CCTV는 큰 도로 위주이고, 차량 교통 흐름 파악이 목적이라 갓길 주차 차량이나 인도 상태 분석에는 적합하지 않을 수 있습니다. 골목길 CCTV는 대부분 방범용이고, 개인정보보호법상 실시간 영상이 외부에 공개되지 않습니다.

대안

  1. 지자체 통합관제센터와 협력: 영상은 센터 안에서 분석하고 위험도 같은 결과값만 받기 (지자체 실증 사업, 공모전, 스마트시티 사업)
  2. 직접 카메라 설치: 테스트 지역 몇 곳에 설치 (안내판 설치 등 법적 의무 준수)
  3. 사용자 제보 사진 분석: 사용자가 찍어 올린 사진을 같은 AI 모델로 분석
  4. 개발 단계에서는 공개 데이터셋 사용: AIhub, Roboflow 데이터로 모델을 먼저 완성
